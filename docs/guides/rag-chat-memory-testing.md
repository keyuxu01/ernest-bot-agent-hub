# RAG 对话记忆与检索改写自测

测试 user 层长期记忆前，先清理测试账号的 Mem0 记忆。Mem0 写入为异步流程，完成一轮后等待约 30 秒再新建会话验证。

通过前端上传、解析并发布以下 PDF。开启审核时还需审核通过。草稿不会进入检索索引，发布后等待索引完成再测试。

## 检索改写

在同一会话依次提问：

1. 出差预估费用超过五千谁还要加签？
2. 那这个找谁？
3. 报销进度要问张敏还是周宁？
4. 知识库上线怎么做灰度？
5. 那这个谁负责？
6. 要找李明还是王芳？
7. 好的谢谢。

预期：第 2 题仍检索差旅和总监加签；第 3 题区分财务张敏与 HR 周宁；第 5、6 题保持在发布 SOP；第 7 题识别为寒暄，不返回“知识库里没有相关内容”。后端日志只记录改写查询长度和是否检索，不记录问题原文。

## Redis 短期记忆

新建会话后依次提问：

1. 我接下来要写一篇给研发看的差旅报销 FAQ，先别展开生产发布。
2. 我刚才说要写什么？先别写什么？

预期：能复述“差旅 FAQ”和“先别讲发布”，不依赖 Mem0。

## Mem0 用户层记忆

会话 A：

> 我是成都研发中心后端。以后回答尽量短，只要本团队能落地的制度，不要展开别的部门流程。

等待约 30 秒后新建会话 B：

1. 按我的偏好，出差报销最需要注意哪三件事？
2. 知识库发布窗口默认审批人是谁？

预期：回答保持简短并偏研发落地；发布窗口从文档引用李明，但不把李明写进用户画像。

## Mem0 会话层记忆

会话 C：

1. 这次只看差旅住宿上限，先不要讲发布封网和请假。
2. 下一步我该看哪？

预期：第二题仍围绕差旅住宿。

随后新建会话 D：

> 我现在该优先处理什么？

预期：新会话不应默认仍在处理住宿标准。用户画像可以跨会话保留，本轮任务不能跨会话泄漏。
